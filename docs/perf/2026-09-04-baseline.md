# Refract performance baseline

Measured 2026-09-04 against a local production build (`next build` + `next start`).
These are the figures the case study quotes, so the method is recorded with them.

## Load

| Metric | Result | Budget | Verdict |
|---|---|---|---|
| LCP, simulated 4G + 4x CPU throttle | **688 ms** | < 2500 ms | pass |
| LCP, unthrottled | 152 ms | -- | -- |
| FCP, throttled | 688 ms | -- | -- |
| JS required before LCP | **188 KB** | -- | -- |
| JS total transferred | 486 KB | -- | -- |
| Page total transferred | 548 KB | -- | -- |

The LCP element is the hero paragraph, not the headline, because the headline is
rendered inside the WebGL scene.

**The 3D payload does not block first paint.** The largest chunk (298 KB transferred,
three.js plus the R3F runtime and drei) is requested at 186 ms and finishes at 222 ms,
after the 152 ms LCP. That is the dynamic import in SceneRoot doing its job: the page
paints its type, then loads a 3D engine.

## Frame rate

Measured in headed Chrome on the real GPU. Headless Chrome falls back to SwiftShader
software rendering, which reports about 3 fps for a transmission material and says
nothing useful about the shipped experience.

| Scenario | Result | Budget | Verdict |
|---|---|---|---|
| Idle at hero | **60.1 fps** | 60 | pass |
| Scrolling the full page | **119.6 fps** | 60 | pass |

GPU: ANGLE (Intel UHD Graphics 620, Direct3D11). Worth noting this is modest integrated
graphics rather than a discrete card, so it is close to a floor for desktop hardware
rather than a best case.
